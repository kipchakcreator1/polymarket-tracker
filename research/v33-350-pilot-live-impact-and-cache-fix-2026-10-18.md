**October 18, 2026.** This is production-state observation and independently tested code, not a profitability evaluation.

## Verified live pilot

The live `v3.3-wallet-research` state now reports **346 monitored cursor keys**, `last_run.watching=346`, `request_errors=0`, and `poll_gaps=0`. The existing 300 are unchanged; the extra 46 are from a shortlist that still applies old CLOSED-snapshot eligibility and the configured quarantine. The wallet monitoring expansion was made in main via [PR #3](https://github.com/kipchakcreator1/polymarket-tracker/pull/3), which changes only the two `V33_MONITOR_MAX` values to 350.

[350-vs-300 live evidence audit](https://github.com/kipchakcreator1/polymarket-tracker/actions/runs/39122934947): the additional 46 generated **12 original-book quoted sports observations in the preceding one-hour window** across **7 distinct wallets** and **10 market conditions**. All 12 retained decision labels were `blocked_recent`. They sent **0** new BUY notifications. The reconstructed original 300 had 97 book-quoted observations in the same one-hour window, likewise 0 marked sent. Over the report's **24-hour dedup history**, the added group had 18 quoted observations and 0 sent; the original group retained 869 quoted observations and 3 marked Telegram-sent. All samples are limited to bounded 900-entry quote evidence, and current historical reconstruction is not a causal performance comparison. These 12 quotes might have been blocked for different recent-history reasons; the quote journal does not contain the exact loss-reason by wallet.

## Two narrow production fixes, separate from risk rule changes

1. [PR #4](https://github.com/kipchakcreator1/polymarket-tracker/pull/4) in `main` repairs an inline Python summary `SyntaxError`. The push-run [#39116506430](https://github.com/kipchakcreator1/polymarket-tracker/actions/runs/39116506430) performed **45 real polls, errors=0**, and persisted v3.3 state before the final summary Python expression failed due to a missing comma. Workflow therefore displayed a false failure. New workflow code is corrected; the current runner must finish with it before success is independently confirmed.

2. [PR #5](https://github.com/kipchakcreator1/polymarket-tracker/pull/5) in `v3.3-wallet-research` repairs a reproduced intra-poll time skew in **four independent caches**: `recent_form_cache`, `active_form_cache`, `politics_cache`, `market_focus_cache`. The monitor samples `now` before public trade/API work; these cache entries are written with later `checked_at` timestamps. Strict end-of-poll cleanup `0 <= now - checked_at` could discard newly computed risk and metadata. Real saved state before the new runner picked up PR #5 had **zero keys in each of those four caches**, even while sports BUY quote verification and risk veto counters increased. The replacement `keep_checked_cache` permits only the already existing **900-second bound** for data written after poll start, continues to prune stale and unselected keys, and leaves the existing *at-use* risk freshness and fail-closed conditions unchanged. It adds saved cache counts to `last_run` for field verification. The user-visible consequence is expected to be fewer redundant API lookups / repeat unverified errors, **not guaranteed more BUY alerts**.

[All research/audit tests, 240/240](https://github.com/kipchakcreator1/polymarket-tracker/actions/runs/39123252637) passed, including 111 v3.3 signal tests and an integration test proving that delayed cache writes survive `main()` JSON persistence. A running long-lived Python process checked out before PR #5 can still have the old code until the next monitoring session checks out the updated research branch. Do not claim the cached-key fix is live until `last_run.cached_risk_wallets` / `cached_sports_market_meta` are present and nonzero in a new completed checkpoint.
